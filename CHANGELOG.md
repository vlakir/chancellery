# Changelog

История заметных изменений. Формат — упрощённый
[Keep a Changelog](https://keepachangelog.com/).

Записи группируются по версиям или датам релизов. Для проектов без
формального версионирования допустимо использовать дату как заголовок.

Категории:
- **Added** — новая функциональность.
- **Changed** — изменения в существующей функциональности.
- **Fixed** — исправления багов.
- **Removed** — удалённая функциональность.
- **Deprecated** — то, что помечено к удалению, но пока работает.
- **Security** — изменения, важные с точки зрения безопасности.

Если изменение связано с задачей из `BOARD.md` / `BACKLOG.md`,
запись **обязательно** содержит T-ID в скобках, например:
`Added: Превью постов в Telegram (T<NNN>).` Это сохраняет уникальность
T-ID между релизами — `CHANGELOG.md` единственное persistent-
хранилище номеров завершённых задач (см. правило нумерации
в `README.md`).

## [0.1.0] — 2026-09-05

### Added
- Движок русского склонения, перенесённый из «Дьяка» 0.3.3 (T001):
  ФИО и его части с автоопределением рода, инициалы в шести формах,
  универсальный фраз-движок для должностей и подразделений, воинские и
  служебные звания.
- Рендер `docx` по шаблону с русской разметкой (T001): падежные фильтры
  `ип`/`рд`/`дт`/`вн`/`тв`/`пр`, согласование по полу фильтром `согл`,
  строгий режим неизвестных переменных, чистка пустых значений вместе с
  осиротевшей пунктуацией.
- Распознавание колонок по заголовку и содержимому, чтение таблицы
  `xlsx` с учётом пользовательского фильтра и скрытых строк,
  уникальные имена выходных файлов, `pydantic`-конфигурация ручных
  переопределений форм (T001).
- Обратная сборка размеченного шаблона из готового документа и строки
  данных (T001).
- Сухой прогон `check_table`: проверка склонения, пола и шаблона без
  записи файлов (T001).
- Высокоуровневый сценарий `generate_documents` / `reverse_template` —
  таблица + шаблон + конфиг → документы одним вызовом (T001).
- Порт прогресса `ProgressSink`: ход работы отдаётся потребителю через
  фабрику от числа строк, поэтому обвязка терминала в зависимости
  библиотеки не попадает (T001).
- Прогон четырёх гейтов в CI на каждый push и pull request (T001).
- Выкладка на публичный PyPI скриптом `scripts/publish.sh`: четыре
  гейта, сборка, проверка артефактов `twine`, загрузка (T003).
- Лицензия MIT, метаданные пакета (classifiers, ссылки, ключевые слова)
  и маркер `py.typed` — без него mypy у потребителей не видел бы типы
  библиотеки (T003).

### Changed
- Корень иерархии ошибок переименован `DyakError` → `ChancelleryError`
  (T001).

### Removed
- `PdfExportError` в библиотеку не переехал: экспорт в PDF — вызов
  внешнего `soffice` и остаётся заботой приложений (T001).

### Retrospective

- **Что зашло.** Приёмка по эталону донора: сессия «Дьяка» сняла снимок
  поведения 0.3.3 и отдала скрипт сверки, а библиотека прогнала его у
  себя через тонкую обвязку — ещё до того, как «Дьяк» начал переезжать.
  Расхождение искалось бы на своей стороне, а не в чужом репозитории;
  на такой приёмке перенос перестаёт быть верой в диффы. Второе, что
  сработало, — переписка двух сессий по фактуре: колбэк-прогресс
  выглядел разумно и молча сломал бы чужое окно, а поймано это было
  до единой строки кода.
- **Что не зашло.** Обещание публикации в спеке было дано без проверки
  предусловий: Trusted Publishing требует ручного шага владельца
  учётной записи, и обнаружилось это на последнем шаге, когда всё уже
  было написано. Дважды по ходу приходилось чинить контракт задним
  числом (`read_table` и нормализаторы конфига не попали в `__all__`) —
  список публичных имён набирался по памяти вместо вычитки.
- **Правки методики.** Проектный `CLAUDE.md` пополнился правилом про
  русский язык комментариев и докстрингов. Стоит завести привычку: если
  acceptance спеки упирается во внешний сервис, проверять предусловия
  на этапе analyze, а не при выпуске.
