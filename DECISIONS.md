# Architecture Decisions

ADR-Lite: компактный лог архитектурных решений с обоснованиями.
Цель — через полгода можно ответить на вопрос «а почему мы тогда так
сделали?», не реконструируя контекст по коммитам.

## Формат

Каждое решение — короткий блок:

- **Дата** — когда принято.
- **Решение** — что решили (1 строка).
- **Контекст** — какая задача / ограничение к нему привели.
- **Альтернативы** — что рассматривали и почему отвергли.
- **Последствия** — что это нам теперь даёт и чего лишает.

Решения не редактируются после фиксации. Если решение пересмотрено —
добавляется новый блок со ссылкой на старый, старый помечается как
«Заменено решением от <дата>».

### 2026-09-05 — Отдельный репозиторий-библиотека, а не extras внутри «Дьяка» (T001)

- **Контекст:** движок склонения и рендера, выросший в «Дьяке»,
  понадобился второму проекту («Летопись», формирование приказов) и
  явно понадобится третьему. Копировать код между проектами — прямое
  нарушение DRY, главного принципа Разработчика.
- **Альтернативы:**
  - Один пакет `dyak` с extras (движок ставится без Qt и CLI) —
    отвергли: библиотека остаётся придатком одного приложения, её
    релизный цикл привязан к выпускам «Дьяка», а имя навязывает
    чужому проекту чужую родословную.
  - Два дистрибутива из одного репозитория (`dyak-core` + `dyak`) —
    отвергли: та же привязка имени, плюс каждая правка движка стоит
    двух синхронных версий.
- **Последствия:** библиотека живёт своей жизнью, «Дьяк» становится её
  потребителем наравне с «Летописью». Плата: два репозитория, два CI,
  два набора досок; правка движка ради «Дьяка» — это PR в чужой
  репозиторий и выпуск версии.

### 2026-09-05 — Имя `chancellery`: не транслит и не производное от потребителя (T001)

- **Контекст:** нужно имя для общей библиотеки; оно же имя пакета,
  импорта и репозитория.
- **Альтернативы:**
  - `dyak-core` / `djak-core` — отвергли по двум причинам: общая
    библиотека не должна называться по одному из потребителей
    («Летописи» имя чужое), плюс расхождение написаний (репозиторий и
    пакет `dyak`, локальная папка `djak`) породило бы третий вариант.
  - `skoropis` (скоропись) — понравилось по смыслу, отвергли: транслит,
    которого Разработчик не выносит.
  - `rescript` (рескрипт, и одновременно «переписать») — отвергли:
    тёзка, существующий язык программирования во фронтенде; поисковая
    выдача была бы зашумлена.
  - `declension` — отвергли: имя сужает проект до склонения, тогда как
    в нём уже рендер `docx` и обратная сборка шаблона.
  - `ukase`, `charter`, `scribe`, `chancery`, `cursive`, `shorthand` —
    часть отвергнута по смыслу, часть занята на PyPI.
- **Последствия:** `chancellery` — канцелярия, то самое присутственное
  место, где служил приказный дьяк: перекличка с «Дьяком» есть, но
  подчинения нет. Плата: одиннадцать букв и двойная «l» — источник
  опечаток в импортах.

### 2026-09-05 — Границы: в библиотеку уезжает весь документный конвейер (T001)

- **Контекст:** нужно провести границу между библиотекой и «Дьяком»
  так, чтобы «Летопись» не тащила к себе чужой GUI и чужой формат
  конфигурации, а «Дьяк» не остался пустой оболочкой без смысла.
- **Альтернативы:**
  - Только движок склонения и рендер, без `reverse` — отвергли:
    обратная сборка опирается ровно на тот же движок (склоняет
    кандидатов и ищет совпадения), граница разрезала бы связный кусок
    посередине.
  - Движок + рендер + `reverse`, но чтение `xlsx` и YAML-конфиг
    остаются в «Дьяке» — рассматривали всерьёз; отвергли в пользу
    более широкой границы: сценарий «таблица + шаблон → документы»
    целиком полезен и третьим потребителям.
- **Последствия:** уезжают `domain`, `errors`, `inflection`, `render`,
  `columns`, `config`, `io`, `reverse`. В «Дьяке» остаются GUI, CLI,
  PDF-экспорт, scaffold и Windows-сборка. Плата: формат конфигурации и
  колоночная модель становятся публичным контрактом — менять их можно
  будет только версией, а «Летопись» ими не воспользуется.

### 2026-09-05 — Библиотека объявляет `[build-system]`, в отличие от «Дьяка» (T001)

- **Контекст:** «Дьяк» намеренно живёт без `[build-system]` и
  запускается через `python -m dyak` (его ADR от 2026-06-21).
  Библиотеку нужно собирать в колесо и публиковать.
- **Альтернативы:** сохранить единообразие с «Дьяком» и ставить
  зависимость из git — отвергли: без версий, без кеша колёс, и лишняя
  точка отказа в Windows-сборке потребителя.
- **Последствия:** решение «Дьяка» здесь не действует; расхождение
  сознательное и относится только к упаковке.

### 2026-09-05 — Только русский язык, без точки расширения (T001)

- **Контекст:** соблазн заранее спрятать движок склонения за
  интерфейс «языкового движка», чтобы потом добавить другие языки.
- **Альтернативы:** заложить абстракцию сразу — отвергли: потребителя
  для неё не существует, а цена платится сейчас и в каждом чтении кода.
- **Последствия:** русские падежи, русские теги шаблона, `pymorphy3` и
  `petrovich` — прямо в ядре. Если второй язык когда-нибудь появится
  по-настоящему, абстракцию вводим тогда, зная его требования.

### 2026-09-05 — Версионирование `0.x` и отсутствие своего CLI (T001)

- **Контекст:** публичный API впервые выходит наружу; форма его не
  проверена ни одним потребителем, кроме самого «Дьяка».
- **Альтернативы:**
  - Сразу `1.0` с гарантиями SemVer — отвергли: каждая правка формы
    API стоила бы мажорной версии, а шлифовка ещё вся впереди.
  - Тонкий CLI «для отладки» — отвергли: тянет в чужой проект
    командную обвязку и заводит у библиотеки второе лицо.
- **Последствия:** до `1.0` ломаем API свободно, оба потребителя свои
  и чинятся тем же днём. Переход к `1.0` — когда форма устоится на
  двух живых потребителях.
